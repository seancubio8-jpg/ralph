04 / HOW I APPROACH PROBLEMS

Think clearly.
Test step by step.

I approach problems by understanding the issue, checking possible causes, and testing solutions one at a time. I focus on finding the main cause instead of making random changes. These examples show common technical problems and how I would troubleshoot them.

01

Website Cannot Connect to Database

Possible causes: The MySQL service is not running, the database credentials are incorrect, or the database name is wrong.

Diagnostic approach: Check the database service, connection settings, database name, and error message.

Lesson: Check the database configuration and test the connection before changing other code.
02

PHP Page Reports an Undefined Function

Possible causes: The function is missing, its name is misspelled, or a required PHP file was not included.

Diagnostic approach: Read the error message, search for the function, and check the include or require statements.

Lesson: Error messages help identify the source of a problem and avoid unnecessary code changes.
03

Website Works Locally but Not on Hosting

Possible causes: Incorrect file paths, case-sensitive filenames, missing files, or different database settings.

Diagnostic approach: Compare local and hosted versions, check file locations and database settings, and review server logs.

Lesson: Test after deployment because the hosting environment may work differently from a local computer.
04

User Cannot Log In

Possible causes: Incorrect credentials, validation errors, a password verification issue, or a database connection problem.

Diagnostic approach: Test valid and invalid logins, inspect authentication logic, and check errors without exposing sensitive information.

Lesson: Test usability and security. Passwords should never appear in error messages or logs.
05

Excel Results Do Not Look Correct

Possible causes: Incorrect formulas, missing data, numbers stored as text, or an incorrect cell range.

Diagnostic approach: Review the formula, selected cells, data format, and compare the result with a manual calculation.

Lesson: Accurate results depend on clean data, correct formulas, and checking calculations.

My Problem-Solving Process

A simple process I can follow when working on programming tasks, system errors, and technical issues.

01

Understand

Identify the problem and expected behavior.

02

Investigate

Check error messages, code, data, and settings.

03

Test

Try one solution at a time and observe the result.

04

Verify

Confirm the fix works and check for other issues.

05

Learn

Record the cause and how to prevent it next time.

My goal is not just to fix a problem, but also to understand why it happened and how I can improve my skills as an IT student and future developer.
